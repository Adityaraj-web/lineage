# F04 — Testnet deployment + agent accounts with function-call keys only

Branch: `f04-deploy` · Commit prefix: `F04:` · Merge: `--no-ff` into `main`

## Goal

One command deploys the whole Lineage demo to NEAR testnet, and a second command proves it is set up correctly. The second command must work for **anyone with no NEAR account**, against our live deployment, using only `deployments/testnet.json` and public RPC views. A judge (or an AI screener) runs `npm install && npm run verify:deploy` and gets a green checklist.

Judges who want their own copy can run `npm run deploy` with their own funded testnet account.

## Context

- Contracts (merged): `contracts/vault` (`lineage-vault`), `contracts/registry` (`lineage-registry`), `contracts/mock-usdc` (`lineage-mock-usdc`). They are members of the Cargo workspace at the repo root.
- Build with `cargo near build non-reproducible-wasm` inside each crate folder. Because this is a workspace, output lands in the **repo-root** `target/near/<crate_name>/<crate_name>.wasm` with underscores (`lineage_vault`, `lineage_registry`, `lineage_mock_usdc`). Confirm the real paths after the first build and use them; the deploy script fails with "run `npm run build` first" if a wasm is missing.
- Owner/root account: `lineage-aditya.testnet` (key in the legacy keychain at `~/.near-credentials/testnet/lineage-aditya.testnet.json`, field `private_key`). `deploy` takes the root from env `LINEAGE_ROOT` with no default (fail with a clear message). Optional `LINEAGE_ROOT_KEY` overrides the keychain file.
- tUSDC has 6 decimals. `usdc(n) = BigInt(n) * 1_000_000n`.
- All `U128` values arrive as **JSON strings**. Parse with `BigInt`, compare as `BigInt`, never `Number`.

## Stack

- TypeScript scripts in `scripts/`, run with `tsx`. Root `package.json` with npm scripts: `build`, `deploy`, `verify:deploy`.
- `near-api-js` **7.5.x**. Use what the installed `.d.ts` files export: `Account`, `JsonRpcProvider`/`FailoverRpcProvider`, `KeyPairSigner`, `KeyPair`, `actions` (`createAccount`, `transfer`, `addKey`, `deployContract`, `functionCall`, `functionCallAccessKey`, `fullAccessKey`), `account.signAndSendTransaction({ receiverId, actions })`, `provider.viewAccessKeyList`, `teraToGas`, `nearToYocto`. Do not use v4/v5 APIs (`connect`, `keyStores`, `WalletConnection`).
- RPC: env `NEAR_RPC_URL`, default `https://test.rpc.fastnear.com`, with `https://rpc.testnet.fastnear.com` and `https://near-testnet.drpc.org` as failover. Do **not** use `rpc.testnet.near.org` (deprecated, heavily rate-limited).
- Secrets (agent private keys) go in `.env.local` (gitignored). Commit a `.env.example` with every variable name and no values. Public deployment info goes in `deployments/testnet.json` (committed).
- Shared helpers in `scripts/lib/` (network/provider setup, `usdc()`, `view()`, explorer links, a one-line `step()` logger) so F05 can reuse them.

## Accounts to create (all sub-accounts of `$LINEAGE_ROOT`)

| Account | Purpose | Contract | Keys |
|---|---|---|---|
| `usdc.<root>` | Mock USDC | lineage-mock-usdc, `new()` | root's public key, full access |
| `registry.<root>` | P2 resolver, curator = root | lineage-registry, `new({curator: root})` | root's public key, full access |
| `vault.<root>` | **Lineage mode** vault | lineage-vault, `new({owner: root, token: usdc, mode: "Lineage"})` | root's public key, full access |
| `guarded.<root>` | **LimitsOnly** comparison vault | lineage-vault, `new({owner: root, token: usdc, mode: "LimitsOnly"})` | root's public key, full access |
| `agent-l.<root>` | Agent for `vault` | none | **one function-call key only** |
| `agent-g.<root>` | Agent for `guarded` | none | **one function-call key only** |
| `hindi-translator.<root>` | Legit vendor registered in the registry | none | root's public key, full access |
| `alice.<root>` | Owner-signed P1 payee (logo designer) | none | root's public key, full access |
| `vendor-payments.<root>` | Attacker account from the poisoned invoice; clean, never paid before | none | root's public key, full access |

Contract accounts keep the root key so contracts can be redeployed during the hackathon. State this in the README's honest limits (a production deploy would remove the keys and lock the contracts). Plain accounts reuse the root key so the script can sign as them (`hindi-translator` must sign `apply`). Only the agents are restricted.

## Steps the deploy script performs

Idempotent: every step checks chain state first and prints `skip` when nothing needs doing. Running `npm run deploy` twice in a row must change nothing the second time.

1. **Preflight.** Check the four wasm files exist. Check root balance. Estimate the NEAR needed from the real wasm sizes (1 NEAR per 100 KB of code, 1e19 yocto per byte) plus the funding below plus ~0.5 NEAR for gas, counting only accounts that do not exist yet. If short, stop with the shortfall and a pointer to the testnet faucet.
2. **Contract accounts.** For each missing contract account, send **one** transaction from root with `receiverId = <new account>` and actions `[createAccount, transfer, addKey(rootPublicKey, fullAccessKey), deployContract(wasm), functionCall("new", args, 30 Tgas, 0)]`. A batch is atomic: if `new` panics, the account is not created, so there is never a deployed-but-uninitialised contract. Funding: code storage + 1 NEAR for each vault (the vault pays 0.00125 NEAR storage registration per payment), code storage + 0.5 NEAR for `usdc` and `registry`.
3. **Plain accounts** (`hindi-translator`, `alice`, `vendor-payments`): `[createAccount, transfer(0.2 NEAR), addKey(rootPublicKey, fullAccessKey)]`.
4. **Agent accounts.** For each missing agent:
   1. Generate an ed25519 key pair and **write it to `.env.local` first** (`AGENT_L_KEY` / `AGENT_G_KEY`).
   2. Then send one transaction from root with `receiverId = <agent>` and actions `[createAccount, transfer(2 NEAR), addKey(agentPublicKey, functionCallAccessKey(<its vault>, ["request_payment"], 2 NEAR allowance))]`.
   3. Do **not** use `account.createAccount` / `createSubAccount` helpers: they add a full-access key.
   4. Save the creation tx hash. It is the on-chain proof that a full-access key never existed on this account.

   If an agent account already exists but its key is not in `.env.local`, stop with a clear error. The account has no full-access key, so nobody can add a new key to it; the fix is to use a fresh root.
5. **Token setup.** `storage_deposit({account_id: vault})` and the same for `guarded` on `usdc` (attach 0.00125 NEAR; skip if `storage_balance_of` is not null). `mint({account_id: root, amount: usdc(2000)})` only if root holds less than `usdc(1000)`. For each vault whose `get_config().balance` is below `usdc(500)`, root calls `ft_transfer_call({receiver_id: vault, amount: <the difference>, msg: ""})` with 1 yocto and 100 Tgas.
6. **Registry.** If `get_service({id: "translate-hi"})` is null, `hindi-translator` calls `apply({id: "translate-hi", price: usdc(25), description: "EN→HI landing page translation"})`. Do **not** re-apply an existing service: re-applying resets it to Pending. If its status is not `Verified`, root (curator) calls `verify({id: "translate-hi"})`.
7. **Task 0 on both vaults**, only if `get_config().task_count == 0` (root, 1 yocto attached, 30 Tgas):
   - agent: the matching agent account
   - instruction: "Get our landing page translated to Hindi via the verified registry, and pay Alice up to 20 tUSDC for the logo."
   - budget `usdc(100)`, max_per_payment `usdc(50)`, ttl_minutes `20160` (14 days, so the mandate outlives judging)
   - signed_payees: `[{account_id: alice, max_amount: usdc(20), label: "Alice — logo"}]`
   - resolvers: `[registry]`
8. **Write `deployments/testnet.json`** (shape below).

## `deployments/testnet.json` shape

```json
{
  "network": "testnet",
  "root": "lineage-aditya.testnet",
  "explorer": "https://testnet.nearblocks.io",
  "contracts": { "usdc": "...", "registry": "...", "vault": "...", "guarded": "..." },
  "agents": {
    "vault":   { "account": "agent-l....", "publicKey": "ed25519:...", "createTx": "..." },
    "guarded": { "account": "agent-g....", "publicKey": "ed25519:...", "createTx": "..." }
  },
  "actors": { "alice": "...", "hindiTranslator": "...", "vendorPayments": "..." },
  "registry": { "translate-hi": { "payee": "...", "price": "25000000" } },
  "tasks": { "vault": 0, "guarded": 0 },
  "deployedAt": "ISO-8601"
}
```

Public keys and tx hashes are public. No private keys in this file.

## Acceptance tests (write `scripts/verify-deploy.ts` FIRST and watch it fail, then make it pass)

`npm run verify:deploy` reads `deployments/testnet.json` (or `--file <path>`), needs **no account and no keys**, prints one ✔/✘ line per check, and exits 0 only if every check passes:

- `vault.get_config().mode === "Lineage"`, `guarded.get_config().mode === "LimitsOnly"`, both `owner === root`, both `token === usdc`, neither frozen.
- For each vault, `usdc.ft_balance_of(vault) === get_config().balance` (the vault's books match the token ledger). If `payment_count == 0`, the balance is also exactly `usdc(500)`. Print the balance in tUSDC.
- `registry.lineage_resolve({reference: "translate-hi"})` returns payee `hindi-translator.<root>` and amount `"25000000"`; `lineage_resolve({reference: "vendor-payments"})` returns `null`.
- Each agent account has **exactly one** access key; it is a **FunctionCall** key; its receiver is its own vault; its method names are exactly `["request_payment"]`; its public key matches `deployments/testnet.json`. Use `viewAccessKeyList`. Print the key and the explorer link to the creation tx; this is what judges check.
- `get_task({task_id: 0})` exists on both vaults with the expected agent, budget, max_per_payment, one signed payee (alice, `usdc(20)`), and `resolvers == [registry]`.

Signed negative checks run only when `.env.local` has the agent keys (otherwise print `skipped: no agent keys (run as the deployer)` and do not fail). Each must fail with the **specific** access-key error, not just any error, because a contract panic like "Owner only" would also make a naive test pass:

- `agent-l` key calls `approve_payment({payment_id: 0})` on `vault` with 0 deposit → method-name mismatch.
- `agent-l` key calls `request_payment` on `guarded` → receiver mismatch.
