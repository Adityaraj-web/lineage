# F04 — Testnet deployment + agent accounts with function-call keys only

Branch: `f04-deploy` · Commit prefix: `F04:` · Merge: `--no-ff` into `main`

## Goal

One command deploys the whole Lineage demo to NEAR testnet, and a second command proves it is set up correctly. Judges must be able to reproduce it from the README with their own testnet account.

## Context

- Contracts (merged): `contracts/vault` (`lineage-vault`), `contracts/registry` (`lineage-registry`), `contracts/mock-usdc` (`lineage-mock-usdc`).
- Build each with `cargo near build non-reproducible-wasm` inside its crate folder; output lands in `target/near/<crate_name>/<crate_name>.wasm`.
- Owner/root account: `lineage-aditya.testnet` (key in the legacy keychain at `~/.near-credentials/testnet/lineage-aditya.testnet.json`). Scripts must take the root account from env `LINEAGE_ROOT`, defaulting to nothing (fail with a clear message), so judges can use their own account.
- tUSDC has 6 decimals. `usdc(n) = n * 1_000_000`.

## Stack

- TypeScript scripts in `scripts/`, run with `tsx`. Root `package.json` with npm scripts.
- NEAR JS: `near-api-js` (v7.x) / `@near-js/*`. Verify method names against the installed package's types before writing code — do not rely on memory of older v4/v5 APIs.
- Secrets (agent private keys) go in `.env.local` (already gitignored). Public deployment info goes in `deployments/testnet.json` (committed).

## Accounts to create (all sub-accounts of `$LINEAGE_ROOT`)

| Account | Purpose | Contract |
|---|---|---|
| `usdc.<root>` | Mock USDC | lineage-mock-usdc, `new()` |
| `registry.<root>` | P2 resolver, curator = root | lineage-registry, `new({curator: root})` |
| `vault.<root>` | **Lineage mode** vault | lineage-vault, `new({owner: root, token: usdc, mode: "Lineage"})` |
| `guarded.<root>` | **LimitsOnly** comparison vault | lineage-vault, `new({owner: root, token: usdc, mode: "LimitsOnly"})` |
| `agent-l.<root>` | Agent for `vault` | none — **function-call key only** |
| `agent-g.<root>` | Agent for `guarded` | none — **function-call key only** |
| `hindi-translator.<root>` | Legit vendor registered in the registry | none |
| `alice.<root>` | Owner-signed P1 payee (logo designer) | none |
| `vendor-payments.<root>` | Attacker account from the poisoned invoice; clean, never paid before | none |

## Steps the deploy script performs (idempotent: skip anything that already exists)

1. Check root balance. Estimate the NEAR needed (contract code costs ~1 NEAR per 100 KB of wasm; the vault is ~223 KB) and stop with a clear message if short, pointing to the testnet faucet.
2. Create sub-accounts. Contract accounts get enough NEAR for code storage plus ~1 NEAR headroom (the vault pays 0.00125 NEAR storage registration per new payee). Plain accounts get ~0.5 NEAR.
3. Deploy + init the four contracts.
4. **Agent accounts:** create each with **only** a function-call access key: receiver = its vault, method names = `["request_payment"]`, allowance = 1 NEAR. No full-access key may ever exist on these accounts. Fund each with ~2 NEAR for gas. Save the private keys to `.env.local` as `AGENT_L_KEY` / `AGENT_G_KEY`.
5. Token setup: `storage_deposit` for both vaults on the token; `mint` 2,000 tUSDC to root; root calls `ft_transfer_call` of 500 tUSDC to each vault (msg `""`, 1 yocto attached, enough gas).
6. Registry: `hindi-translator` calls `apply({id: "translate-hi", price: usdc(25), description: "EN→HI landing page translation"})`; root (curator) calls `verify({id: "translate-hi"})`.
7. Create task 0 on **both** vaults (root, 1 yocto attached):
   - agent: the matching agent account
   - instruction: "Get our landing page translated to Hindi via the verified registry, and pay Alice up to 20 tUSDC for the logo."
   - budget `usdc(100)`, max_per_payment `usdc(50)`, ttl_minutes `2880`
   - signed_payees: `[{account_id: alice, max_amount: usdc(20), label: "Alice — logo"}]`
   - resolvers: `[registry]`
8. Write `deployments/testnet.json` with every account id, mode, task id, and the explorer links.

## Acceptance tests (write `scripts/verify-deploy.ts` FIRST and watch it fail, then make it pass)

`npm run verify:deploy` exits 0 only if all are true:

- `vault.get_config().mode === "Lineage"` and `guarded.get_config().mode === "LimitsOnly"`; both `balance === usdc(500)`; neither frozen.
- `registry.lineage_resolve({reference: "translate-hi"})` returns payee `hindi-translator.<root>` and amount `usdc(25)`; `lineage_resolve({reference: "vendor-payments"})` returns `null`.
- Each agent account has **exactly one** access key, it is a **FunctionCall** key, receiver is its own vault, method names are exactly `["request_payment"]`. (Check with the RPC `view_access_key_list` query.) This is the claim judges will check on the explorer, so print it clearly.
- `get_task({task_id: 0})` exists on both vaults with the expected budget, one signed payee and the pinned registry.
- Negative check: a call to `approve_payment` signed by an agent key is rejected (the function-call key cannot call that method).
