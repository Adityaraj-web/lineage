# F05.1 — Memo truncation on a character boundary + vault code upgrade

Branch: `f051-memo-fix` · Commit prefix: `F05.1:` · Merge: `--no-ff` into `main`

## Problem

`request_payment` shortens the memo with `memo.truncate(MAX_MEMO_LEN)`. `String::truncate` counts **bytes** and panics when byte 200 falls inside a multi-byte UTF-8 character (for example "—", 3 bytes). The memo comes from untrusted input (the agent copies the email subject), so a crafted subject makes an honest payment request fail. No funds move (the panic reverts the call), but it is a denial-of-service on the agent and a visible bug for anyone reading `lib.rs`. `agent/tools.ts` already guards against it on the client side; the contract must not depend on that.

## Change

1. `contracts/vault/src/lib.rs`: replace `memo.truncate(MAX_MEMO_LEN)` with a truncation that steps back to the nearest character boundary at or below `MAX_MEMO_LEN` (`is_char_boundary`). Nothing else in the contract changes: no new fields, no changed types, so the stored state layout is identical and no migration is needed.
2. Unit tests in `contracts/vault/src/tests.rs`, written **first** and seen to fail (panic) on the current code:
   - A 250-byte memo made of "—" characters: `request_payment` succeeds, the stored memo is ≤ 200 bytes, valid UTF-8, and a prefix of the input.
   - A memo whose byte 200 falls exactly on a boundary: kept at exactly 200 bytes.
   - A short memo is unchanged.
3. `scripts/upgrade-vaults.ts` + `npm run upgrade:vaults` (root key, idempotent):
   - Build check: the vault wasm exists.
   - For `vault` and `guarded`: if the on-chain `code_hash` already equals the local wasm's hash (base58 of sha256), `skip`. Otherwise send one transaction from root with the single action `deployContract(wasm)`. **No `new` call**: state is kept.
   - After each upgrade, call `get_config` to prove the old state is readable by the new code.
   - Supports `--dry-run` (prints the hashes and what it would do).
4. `scripts/verify-deploy.ts`: add a check that `vault` and `guarded` have the **same** `code_hash`, and print it. This is the on-chain proof that the comparison is fair (only `mode` differs).
5. CLAUDE.md: Status, Commands (`npm run upgrade:vaults`), and the pitfall about byte-indexed `String` operations in Rust.

## Acceptance

- `cargo test` passes (all old tests + the new ones). The new memo test panicked before the fix.
- `npm run upgrade:vaults -- --dry-run` shows both vaults would be upgraded, from the old hash to the new one.
- After Adityaraj runs `npm run upgrade:vaults`: a second run prints only `skip`; `npm run verify:deploy` passes 13/13 including the same-code-hash check; `npm run demo` passes again (state from task 0 and task 1 still readable).

Any other contract change. The registry and mock-usdc are untouched.
