# F08: Mandate builder, agent `--task`, final polish, Vercel deploy

Branch: `f08-mandate-builder` · Commit prefix: `F08:` · Merge: `--no-ff` into `main` · Five phases, stop after each for review.

## Goal

1. The **owner** can sign a new task mandate (`create_task`) from the Lineage vault page, in their own wallet. "Use demo mandate" fills the form from task 0.
2. `npm run demo -- --task <id>` runs the demo agent against that task with **only the agent's function-call key**. It does no owner setup and never loads the root key.
3. Final UI polish: one dominant hue per page with the rest near black, a freeze switch whose off state meets 3:1 contrast, and no error toast for a single RPC blip.
4. The static site is live on Vercel.

The contract does not change. The UI only builds a call the contract already checks: owner only, exactly 1 yocto.

## Phase 1: Pure mandate logic (web, tests first) · `/effort medium`

New `web/src/lib/mandate.ts`:

```ts
export const TASK_GAS = "50000000000000";           // 50 Tgas (event + up to 20 payees); unused gas is refunded
export const INSTRUCTION_MAX_BYTES = 1000;
export const LABEL_MAX = 64;                          // UI rule, code points
export const BUDGET_MAX = 10_000n * 1_000_000n;       // UI sanity cap, base units
export const TTL_OPTIONS = [60, 1440, 10080, 20160] as const;   // 1 h, 1 day, 7 days, 14 days

export interface MandateForm {                         // raw strings, exactly as typed
  agent: string; instruction: string; budget: string; maxPerPayment: string; ttlMinutes: number;
  payees: { accountId: string; max: string; label: string }[];
  resolvers: string[];
}
export interface CreateTaskArgs {                      // exact contract JSON
  agent: string; instruction: string; budget: string; max_per_payment: string; ttl_minutes: number;
  signed_payees: { account_id: string; max_amount: string; label: string }[];
  resolvers: string[];
}
export type FieldErrors = Partial<Record<string, string>>;   // keys: "agent", "budget", "payees.2.accountId", ...
export function parseUsdc(s: string): bigint | null;           // "12.5" → 12_500_000n
export function toUsdcInput(base: string): string;             // "12500000" → "12.5" (no grouping)
export function isAccountId(s: string): boolean;
export function validateMandate(f: MandateForm): { ok: true; args: CreateTaskArgs } | { ok: false; errors: FieldErrors };
export function createTaskTx(vault: string, args: CreateTaskArgs): OwnerTx;
export function demoMandateForm(task0: Task): MandateForm;
export function createdTaskId(result: TxResult): number | null;
export function emptyMandateForm(agent: string, registry: string): MandateForm;
```

Rules:
- `parseUsdc`: the trimmed input must match `^\d+(\.\d{1,6})?$`. No sign, exponent, commas or spaces inside. Returns `bigint`, never `Number`.
- `isAccountId`: 2–64 chars, `^(([a-z\d]+[-_])*[a-z\d]+\.)*([a-z\d]+[-_])*[a-z\d]+$`. No lower-casing or trimming to make a match; uppercase input shows "Use lowercase".
- `validateMandate` (errors are short, user-facing):
  - agent is a valid account id.
  - instruction has at least one non-space character and is ≤ 1000 bytes by `new TextEncoder().encode(..).length`.
  - budget > 0 and ≤ `BUDGET_MAX`.
  - max per payment > 0 and ≤ budget.
  - ttl is one of `TTL_OPTIONS`.
  - 0–20 payees. Each payee: valid account id, max > 0 and ≤ budget, label 1–64 code points after trim. No duplicate account ids.
  - 0–5 resolvers, each a valid account id, no duplicates.
  - An empty form row (all fields blank) is dropped, not an error.
  - Output strings are trimmed and amounts become decimal base-unit strings.
- `createTaskTx`: `{ receiverId: vault, actions: [{ type: "FunctionCall", params: { methodName: "create_task", args, gas: TASK_GAS, deposit: "1" } }] }`. It takes `CreateTaskArgs` only, so a component can't build a call from the raw form.
- `demoMandateForm(task0)`: copies agent, instruction, budget, max, payees (with labels) and resolvers from the live task 0. ttl = `(expires_at_ms − created_at_ms) / 60000` if that is in `TTL_OPTIONS`, else 1440.
- `emptyMandateForm` starts with agent = `AGENT_IDS.vault`, resolvers = `[CONTRACTS.registry]`, ttl 1440, no payees.
- `tx.ts`: `TxResult` gains `value: string | null`, the base64-decoded `status.SuccessValue` (UTF-8). It is null when the value is absent or empty, or the tx failed. Update the existing fixtures. `createdTaskId` parses `value` as JSON and returns it only when it is a non-negative integer ≤ u32 max.

Acceptance:
- `createTaskTx` → exact receiver, method, args (`toStrictEqual`), gas, deposit. Amounts are strings in the args.
- `validateMandate` table tests. Must cover:
  - the 1000-byte edge (exactly 1000 ok; 999 ASCII + one 2-byte char = 1001 → error);
  - max > budget;
  - "1.1234567";
  - "1e3";
  - "-5";
  - " 12.5 " (ok);
  - uppercase account;
  - duplicate payee;
  - 21 payees;
  - 6 resolvers;
  - a blank payee row dropped;
  - a label of 65 emoji.
- `demoMandateForm(task0 fixture)` → `validateMandate` → args equal `agent/owner.ts demoTaskArgs` for the same names (write the expected object out in the test; do not import across packages).
- `createdTaskId`: `"MTU="` → 15; `""` → null; `"\"x\""` → null; failure → null.
- **Mutation checks (paste the red runs):** deposit `"0"`; budget sent as a `bigint`/number instead of a string; dropping the `max ≤ budget` rule.

## Phase 2: `npm run demo -- --task <id>` (agent, tests first) · `/effort medium`

- `parseArgs` accepts `--task <id>` (a non-negative integer). `--task` implies the Lineage vault: `--task` together with `--only guarded` is an error. `--task 0` is an error ("task 0 is the verify fixture; create a task in the dashboard"). It combines with `--plan-only`.
- In `--task` mode, `main` branches into a separate `runTask(id, planOnly)` that:
  1. **Read-only preflight**, a pure `preflightTask(task, config, agentId, nowMs): string[]`. Each check returns its own error:
     - the task exists;
     - `task.agent === agent-l`;
     - the task is not closed;
     - the task is not expired;
     - the vault is not frozen;
     - mode is `Lineage`.
     A vault balance below `budget − spent` is a printed warning, not an error. Any error → print it and exit 1 before loading any key.
  2. Plans with `scriptedPlanner(inbox, mandateFromTask(task))`, the mandate **from this task**, and prints the plan. `--plan-only` stops here.
  3. Loads only the agent-l key (`agentSigner`). It **never calls `loadRootKey`**, `ensureRootTokens`, `ensureVaultFunds`, `rejectStaleApprovals` or `createRunTask`.
  4. Runs the plan, prints the vault report (`printVault`) and the agent allowance used.
  5. Does **not** write `deployments/demo-run.json`. That file stays the official two-vault run the dashboard reads.
  6. Acceptance:
     - If `sameMandate(task, task0)`, run the vault part of the existing checks on this run's payments: three payments with the expected statuses, provenance, payees and amounts, and nothing paid to vendor-payments.
     - Otherwise print "custom mandate: the contract's answers are above" and pass if no tool call ended in `outcome: "error"`.
     Extract the per-vault part of `checkAcceptance` into `checkVaultPayments(v, run, n): string[]` and use it from both paths. The existing tests must stay green.
- Tests:
  - `parseArgs` cases;
  - `preflightTask`, one test per error;
  - `checkVaultPayments` on a passing and a failing run;
  - a source test asserting that `runTask` (its function body) does not reference `loadRootKey`. Mutation: add the call, show red.
- Read-only check Claude Code may run: `npm run demo -- --task 5 --plan-only` (task 5 exists on the vault). Expected: the same three calls as the official plan. Nothing signs.

## Phase 3: Mandate form on the Lineage vault page · `/effort high`

- **Where:** in the Tasks section of `/vault/vault`, owner only (the F07 gate: `role === "owner"`). The Section `aside` gets a "New task" button that opens the form inline, above the task cards. No modal. Viewer and disconnected see exactly what F07 showed. The Guarded vault page gets nothing; the builder stays vault-agnostic.
- **Form** (`components/vault/MandateForm.tsx`, a Glass card):
  - **Agent:** prefilled, editable. If it isn't agent-l, show the hint: "`npm run demo -- --task` runs only agent-l".
  - **Instruction:** textarea with a bytes-left counter.
  - **Budget** and **Max per payment:** tUSDC inputs, `inputMode="decimal"`, numbers in the sans font.
  - **Expires in:** a segmented control over `TTL_OPTIONS`.
  - **Signed payees:** rows of account / max / label, with "Add payee" (hidden at 20) and a remove button per row.
  - **Resolvers:** rows with add/remove, max 5, and the note "The vault pays exactly what these return. Add only resolvers you trust."
  - Header buttons: **"Use demo mandate"** (shown only if task 0 is in the view) and Cancel.
  - Errors show under each field after a field is touched, or on submit. `aria-invalid` and `aria-describedby` are wired.
- **Confirm (inline, like F07):** "Review" runs `validateMandate`. The confirm summary is rendered from `args`, **not from the inputs**:
  - agent;
  - budget, max per payment;
  - expiry as a duration;
  - each payee with its max and label;
  - each resolver;
  - the instruction as a text node, with full account ids unbroken.
  Then the buttons "Sign in wallet" (primary) and "Edit". The action id is `create-task`, through the same `useOwnerAction` (one action at a time; the inbox and freeze stay disabled while signing).
- **Result:** on success, the form closes and resets, and a result line in the Tasks section shows:
  - "Task #N created", plus the tx hash link and the status pill;
  - "Run the agent on it:" `npm run demo -- --task N` in mono, with a Copy button.
  If `createdTaskId` is null, show "Task created" plus the hash; the refresh shows it. On failure, show the chain reason and keep the form open with its values. `LastAction` and `FreezeSwitch` must ignore the `create-task` id. Check `heldAction` returns null for it.
- **Newest task up front:** `splitTasks` puts the highest task id up front, so a task you just created shows without opening "Earlier tasks". The "latest demo run" chip stays on its task wherever it sits. Update the story tests.
- Tests (jsdom, FakeWallet):
  - owner sees "New task"; viewer and disconnected don't;
  - Guarded never shows it;
  - "Use demo mandate" fills every field;
  - invalid input blocks Review and shows the field error;
  - the confirm shows args-derived values. Type " 12.50 " and the confirm shows 12.5.
  - Sign sends exactly `createTaskTx(vault, args)`;
  - the success line shows "#15" and the command;
  - a failure keeps the values;
  - an instruction containing `<img src=x onerror=alert(1)>` renders as text in the confirm and in the TaskCard.
